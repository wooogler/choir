What changed

This release is mostly maintenance. The scheduler no longer wakes every second when the queue is empty, which takes a measurable bite out of idle CPU on small instances, and the exporter finally reports the queue depth it has been computing internally since the spring. Neither change alters any interface, so an upgrade should be a restart and nothing more. The notes below list the changes an operator is likely to notice.

Upgrading

Stop the service, replace the binary, and start it again. There is no migration, and a rollback to the previous version works without one either. If you run more than one replica you can do this one replica at a time; the two versions speak the same protocol and can run side by side for as long as the upgrade takes.
